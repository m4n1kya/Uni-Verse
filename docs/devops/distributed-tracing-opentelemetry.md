# Distributed Tracing with OpenTelemetry & Jaeger Architecture

## Overview
When a student interacts with Uni-Verse—such as placing a cafeteria order or tracking a campus shuttle—the request traverses multiple service boundaries: browser client runtime $\rightarrow$ Vercel Edge CDN $\rightarrow$ Node.js API Gateway $\rightarrow$ PostgreSQL cluster $\rightarrow$ Redis cache. To diagnose latency bottlenecks and distributed failures instantaneously, Uni-Verse instruments end-to-end **Distributed Tracing** conforming to **OpenTelemetry (OTel)** standards.

---

## 1. End-to-End Trace Propagation Architecture

```
[Client Browser]
  | Span: 'user-click:order-checkout'
  | Injects W3C Header: 'traceparent: 00-4bf92f3577b34da6-00f067aa0ba902b7-01'
  v
[Edge API Gateway]
  | Span: 'gateway:authenticate-and-route' (Duration: 12ms)
  v
[Cafeteria Microservice]
  | Span: 'dining:validate-inventory' (Duration: 18ms)
  | Span: 'dining:create-order-db' (Duration: 8ms)
  v
[PostgreSQL Database]
  | Span: 'SELECT / INSERT cafeteria_orders' (Duration: 4ms)
```

---

## 2. W3C Trace Context Propagation

Every outbound network request generated by the browser application injects standard W3C HTTP headers:

- **`traceparent`**:
  $$\text{version (00)} - \text{trace\_id (16 bytes)} - \text{parent\_span\_id (8 bytes)} - \text{trace\_flags (01)}$$
  Example: `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
- **`tracestate`**: Carries vendor-specific routing metadata across microservices.

## 3. Client-Side OpenTelemetry Web SDK Setup

```typescript
import { WebTracerProvider } from '@opentelemetry/sdk-trace-web';
import { FetchInstrumentation } from '@opentelemetry/instrumentation-fetch';
import { BatchSpanProcessor } from '@opentelemetry/sdk-trace-base';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { registerInstrumentations } from '@opentelemetry/instrumentation';

const exporter = new OTLPTraceExporter({
  url: 'https://telemetry.universe-campus.org/v1/traces',
});

const provider = new WebTracerProvider();
provider.addSpanProcessor(new BatchSpanProcessor(exporter, {
  maxQueueSize: 100,
  scheduledDelayMillis: 2000, // Batch export every 2 seconds
}));

provider.register();

registerInstrumentations({
  instrumentations: [
    new FetchInstrumentation({
      propagateTraceHeaderCorsUrls: [
        /https:\/\/api\.universe-campus\.org\/.*/,
      ],
    }),
  ],
});
```

## 4. Adaptive Tail-Based Sampling Strategy

Transmitting 100% of telemetry traces during high-traffic university registration rushes would overwhelm storage backends and incur unnecessary bandwidth costs. Uni-Verse implements **Adaptive Tail Sampling**:

| Request Profile | Sampling Rate | Rationale |
|---|---|---|
| **Normal Requests ($< 250\text{ ms}$, Status 200)** | $5\%$ random sample | Provides statistically valid baseline latency profiles |
| **Degraded Requests ($> 500\text{ ms}$)** | **$100\%$ full trace capture** | Diagnoses latency regressions and slow database queries |
| **Error Responses (HTTP 4xx / 5xx)** | **$100\%$ full trace capture** | Immediate root-cause analysis for student-facing errors |
